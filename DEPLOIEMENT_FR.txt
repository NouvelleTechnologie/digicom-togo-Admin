DIGICOM TOGO — PAQUET PLAT POUR DÉPLOIEMENT

Tous les fichiers sont à la racine de cette archive : aucun sous-dossier applicatif.

FRONTEND STATIQUE
- Publier les fichiers de cette archive sur un hébergement statique (GitHub Pages ou Netlify).
- Le point d'entrée est index.html. La navigation utilise HashRouter, adaptée à l'hébergement statique.
- Les bibliothèques React et Firebase sont chargées via importmap/CDN. Une connexion Internet est requise.
- La configuration Firebase actuelle est dans config.js. Vérifiez dans Firebase Console que les domaines d'hébergement sont autorisés et que les règles Firestore/Storage protègent les données.
- Le cache du service worker a été renouvelé (digicom-pro-v3) : les utilisateurs récupèrent la nouvelle version au prochain chargement.

SERVICE IA (SERVEUR SÉPARÉ, NON INCLUS ICI)
- Le service IA est un backend Node/Express hébergé sur Render (archive digicom-ai-corrige.zip, dossier serveur/).
- Renseigner l'URL HTTPS de ce service dans index.html (window.DIGICOM_AI_API_URL) AVANT de publier le frontend.
- Variables du serveur : voir serveur/.env.example (GEMINI_API_KEY, FIREBASE_*, FRONTEND_ORIGIN, secours facultatifs).
- Ne jamais mettre une clé API dans les fichiers frontend ni dans GitHub.

CONTRÔLES EFFECTUÉS (passe 2)
- Syntaxe JavaScript vérifiée sur les 19 fichiers .js.
- aiClient.js testé avec un faux serveur : succès, 503 puis succès, 503 répété, 429, 403, réseau coupé, délai dépassé.
- Le composant React DigiComAssistantIA.js n'a pas pu être exécuté ici : sa syntaxe est vérifiée, mais il doit être testé dans le navigateur.

LIMITES
- Ce paquet ne prouve pas que Firebase Auth/Firestore est configuré correctement en production.
- Les fonctions qui nécessitent des règles Firebase, comptes, autorisations ou secrets doivent être testées sur le projet réel.
